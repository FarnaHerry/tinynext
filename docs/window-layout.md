# 窗口布局

TinyNext 是 C++23 模块应用：EUI-NEO 负责窗口和界面，aria2-next 负责下载。
领域任务、视图状态和弹窗状态分别由 `store.tasks`、`store.ui`、`store.dialogs`
管理。窗口整理沿用这套分层与现有单色主题。

## 设计与实现

模式为现有界面的布局整理。参考项目自己的任务卡、添加弹窗和 EUI 0.6.0
本地 DSL / 组件文档；目标是让频繁使用的下载操作更明确。

| 区域 | 组织方式 |
| --- | --- |
| 共用页头 | `Column` 放标题和说明，右侧放页面操作；高度 44，分区间距 12 |
| 下载操作 | 添加下载为文字主按钮；筛选在左，批量操作和排序在右，放不下时拆行 |
| 下载正文 | `drawPanel` 包裹任务卡，任务内容使用 `scrollView`；空列表与空分类有不同提示 |
| 下载底部 | 左侧分类任务数，右侧当前页 / 总页数、每页数量和设置入口 |
| 设置分组 | 一个 `Flow` 按实测文字宽度排列八个分组，保留完整文案 |
| 设置正文与底部 | 表单保持单列滚动；恢复默认在左，放弃和保存在右；引擎操作共用底部区域 |

优先复用 `components::button`、`components::text`、`scrollView` 与项目包装。
页头包装放在 `widgets.cppm`；面板、分隔线与空状态使用少量图元。
颜色全部来自主题，面板恢复 hairline；按钮反馈为 0.14–0.16 秒过渡。
新增文案包含简中、繁中和英文，任务 id 和弹窗交互规则沿用原实现。

## 高 DPI 窗口约束

`Screen` 的单位已经除过 DPI 与 `kUI`，原先只在 `minWindowSize` 乘 `kUI`
会在 2× DPI 的 XWayland 上把 700×500 的最小画布减半，导致添加弹窗截底。
`ensureMinimumCanvas` 使用原生窗口尺寸与 EUI 画布的实际比例，
设置对应的窗口最小尺寸；显示器比例变化后重新换算。它只配置窗口几何，
绘制与输入仍交给 EUI，没有新增线程或逐帧回调。

## 验证

构建目标：`tinynext`，使用 `mcpp build`；`git diff --check` 通过。
Linux / XWayland、2× DPI、`kUI=1.4` 下检查了最小 700×500 逻辑画布和较大窗口：

- 中英文、亮暗主题、空列表、空分类、添加下载与媒体选择弹层。
- 六个本地 HTTP 测试下载的任务卡、两页切换与每页数量弹层。
- 设置通用分组、英文长标签换行、引擎监控及固定底部操作区。
- 请求把窗口缩到 980×700 原生像素后，窗口维持 1960×1400，保证实际画布为 700×500。

测试配置、下载与截图位于临时目录，未写入用户的下载会话。
Windows 和 macOS 未做运行时验证。
